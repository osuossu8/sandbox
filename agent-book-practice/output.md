## **健康管理アプリ 要件定義書**

### 1. プロジェクト概要

#### 1.1. 背景
現代社会において、多忙なライフスタイル、不規則な食生活、高齢化に伴う慢性疾患など、人々の健康に関する課題は多様化・複雑化している。多くの人が健康管理の必要性を感じている一方で、「記録が面倒」「モチベーションが続かない」「どの情報を信じれば良いかわからない」といった理由で挫折するケースが後を絶たない。

#### 1.2. 目的
本プロジェクトは、テクノロジーを活用することで、多様な健康課題やITリテラシーを持つ全てのユーザーが、**「簡単」に、そして「楽しく継続」できる**統合的な健康管理プラットフォームをスマートフォンアプリとして提供することを目的とする。

#### 1.3. 解決する課題
本アプリは、ユーザーが抱える以下の主要な課題を解決する。
*   **記録の手間:** 手動でのデータ入力、特に煩雑な食事記録の負担を、自動化・簡素化によって解消する。
*   **継続性の欠如:** 一人では維持しにくいモチベーションを、ゲーミフィケーションやコミュニティ機能によって支援する。
*   **情報の分断:** 複数のアプリやウェアラブルデバイスに散在する健康データを一元管理し、横断的な分析を可能にする。
*   **データ活用の限界:** 単なる「記録」に留まらず、データに基づいたパーソナライズされた「分析」や「提案」を提供し、ユーザーの具体的な行動変容を促す。
*   **利用の障壁:** ITリテラシーに不安のあるユーザーでも直感的に使えるシンプルなUI/UXを提供する。

### 2. 主要機能

インタビュー結果に基づき、以下の機能を定義する。

#### 2.1. データ入力機能
**要件:** ユーザーの入力負担を最小限に抑え、データの自動収集を最大化する。

| 機能名 | 詳細 | 関連ペルソナ |
| :--- | :--- | :--- |
| **ウェアラブルデバイス連携** | Apple HealthKit, Google Fit等を介し、歩数、睡眠、心拍数等のデータを自動で同期する。 | 佐藤健太, 田中悠斗 |
| **医療機器連携** | Bluetooth対応の血圧計や血糖値測定器から測定データを自動で取り込む。 | 高橋清, 伊藤良子 |
| **食事記録の簡素化** | ・料理の写真からメニューとカロリーをAIが自動解析・入力<br>・レシートや商品のバーコードスキャンによる自動入力 | 鈴木美咲 |
| **ワンタップ記録** | その日の気分、体調、ストレスレベルなどを、アイコンのタップのみで簡単に記録できる。 | 鈴木健二 |
| **服薬管理** | 薬の種類、服用時間を設定し、リマインダーで通知する。服用したかどうかをチェックボックスで記録できる。 | 高橋千代 |

#### 2.2. データ可視化・分析機能
**要件:** ユーザーのITリテラシーや目的に応じて、シンプルにも詳細にもデータを表示・分析できる。

| 機能名 | 詳細 | 関連ペルソナ |
| :--- | :--- | :--- |
| **シンプルダッシュボード** | 歩数、血圧などの主要な指標を、カレンダー形式や大きな文字のシンプルなグラフで表示する。 | 高橋清, 佐藤洋子 |
| **相関関係の可視化** | 「食事内容と血糖値の変動」「睡眠の質と翌日の気分」など、2つの異なるデータの関係性をグラフで重ねて表示する。 | 伊藤良子 |
| **高度なインサイト分析** | 複数のデータ（生理周期、ストレス、睡眠、食事、生産性など）を掛け合わせ、ユーザー独自の健康パターンや相関関係を分析し、テキストでインサイトを提供する。 | 田中沙織, 伊藤里奈 |

#### 2.3. モチベーション維持・行動変容支援機能
**要件:** ユーザーが楽しみながら健康管理を継続できる仕組みを提供する。

| 機能名 | 詳細 | 関連ペルソナ |
| :--- | :--- | :--- |
| **ゲーミフィケーション** | ・友人や他のユーザーと歩数や目標達成度を競うランキング機能<br>・目標達成に応じたバッジやポイントの付与 | 佐藤健太 |
| **パーソナライズド提案** | ・リアルタイムの身体コンディション（睡眠の質など）に基づき、その日の最適なトレーニングメニューや栄養摂取量を提案する。<br>・目標（パフォーマンス向上など）に応じた食事メニューを提案する。 | 田中悠斗, 田中沙織 |

#### 2.4. 共有機能
**要件:** ユーザーの許可に基づき、必要な情報を他者と安全に共有できる。

| 機能名 | 詳細 | 関連ペルソナ |
| :--- | :--- | :--- |
| **レポート出力・共有** | 記録したデータを指定した期間でPDF等のレポート形式に出力し、医師や家族と共有できる機能。 | 伊藤良子 |

### 3. 非機能要件

| 項目 | 要件 |
| :--- | :--- |
| **ユーザビリティ** | ・ITリテラシーの低いユーザーでも迷わず操作できる、直感的でシンプルなUIデザイン。<br>・初心者向けの「シンプルモード」と上級者向けの「詳細モード」など、表示を切り替えられる機能。<br>・初期設定が簡単で、アカウント登録のハードルが低いこと。 |
| **パフォーマンス** | ・アプリの起動、画面遷移、データ同期が高速で、ストレスなく動作すること。 |
| **セキュリティ** | ・健康情報という機微な個人情報を扱うため、通信および保存データの暗号化を徹底する。<br>・不正アクセスを防止するための厳格な認証・認可の仕組みを実装する。<br>・プライバシーポリシーを明確に定め、ユーザーの同意に基づきデータを扱う。 |
| **信頼性・正確性** | ・外部デバイスからのデータ同期やAIによる解析結果が正確であること。 |
| **拡張性** | ・将来的に新しいウェアラブルデバイスや医療機器、データソースに対応できるよう、拡張性の高いアーキテクチャを採用する。 |

### 4. 制約条件

*   **プラットフォーム:** iOSおよびAndroidに対応する。
*   **開発リソース:** 全機能の同時リリースは困難なため、後述の優先順位に基づき段階的に開発・リリースを行う。
*   **外部連携:** 外部デバイスやAPIとの連携は、各提供元の仕様に準拠する。仕様変更に追随するための保守体制が必要となる。

---

### 5. ターゲットユーザー

インタビュー結果から、本アプリのターゲットユーザーは以下の4つのセグメントに大別される。

1.  **健康管理初心者・ライト層:** (鈴木美咲, 鈴木健二, 佐藤洋子)
    *   ニーズ: とにかく簡単で手間なく、日々の健康状態を記録したい。
2.  **高齢者・特定疾患層:** (高橋清, 高橋千代, 伊藤良子)
    *   ニーズ: 血圧・血糖値・服薬など特定の課題を簡単に管理したい。医師と情報を共有したい。
3.  **若年・テクノロジー活用層:** (佐藤健太, 田中悠斗)
    *   ニーズ: 最新のデバイスと連携し、自動で記録したい。ゲーム感覚で楽しみたい。
4.  **健康上級者・データ分析層:** (田中沙織, 伊藤里奈)
    *   ニーズ: 複数データを掛け合わせた高度な分析と、パフォーマンス向上のための具体的な提案が欲しい。

### 6. 優先順位

幅広いユーザー層の獲得とプロジェクトの早期立ち上げのため、以下の通り優先順位を設定する（MoSCoW分析）。

#### Phase 1: MVP (Must - 必須)
*目的: 最も広いユーザー層（初心者・高齢者）の「記録が面倒」「続けられない」という課題を解決し、アプリの基盤を構築する。*
*   **機能:**
    *   簡単な初期設定とシンプルなUI
    *   手動での基本データ入力（体重、血圧、気分など）
    *   ウェアラブルデバイスとの基本連携（歩数、睡眠）
    *   シンプルなデータ可視化（カレンダー、基本グラフ）
    *   服薬管理・リマインダー機能

#### Phase 2 (Should - 推奨)
*目的: ユーザー体験を向上させ、継続利用を促進する。*
*   **機能:**
    *   食事記録の簡素化（バーコードスキャン、写真解析のベータ版）
    *   ゲーミフィケーション（ランキング機能）
    *   医療機器との連携（血圧計など）
    *   レポート出力・共有機能

#### Phase 3 (Could - 可能なら)
*目的: 上級者やデータ活用層のニーズに応え、アプリの付加価値を最大化する。*
*   **機能:**
    *   高度なインサイト分析機能
    *   パーソナライズド提案機能
    *   食事の写真解析機能の精度向上

### 7. リスクと軽減策

| リスク | 軽減策 |
| :--- | :--- |
| **ターゲット層が広すぎ、特徴のないアプリになる** | MVPでは最も広いユーザー層（初心者・ライト層）にフォーカスし、段階的に機能拡張を行う。将来的にはユーザーが目的を選べる「モード切替」機能を導入する。 |
| **食事の写真解析など、AI機能の精度が低い** | 初期はバーコードスキャンやデータベース検索を主とし、AI解析は精度が担保できるまでベータ機能として提供。外部の成熟したAIエンジンの利用も検討する。 |
| **健康情報・個人情報の漏洩** | 開発初期段階からセキュリティ設計を最優先事項とする。データベースの暗号化、通信のSSL/TLS化、脆弱性診断の定期的な実施を行う。 |
| **ユーザーの継続利用率の低下** | 入力の手間を徹底的に削減すると共に、ゲーミフィケーションやポジティブなフィードバックなど、行動科学に基づいた継続を促す仕組みを組み込む。 |
| **外部デバイス連携の不安定性** | まずはApple HealthKit/Google Fitなど、プラットフォーム標準のハブとの連携を優先し安定性を確保する。APIの仕様変更に迅速に対応できる保守体制を構築する。 |
